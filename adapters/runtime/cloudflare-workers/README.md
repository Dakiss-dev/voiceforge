# Cloudflare Workers Runtime Adapter

**Status:** Phase 1, in progress

Hosts the composed receptionist as a Cloudflare Worker. The Receptionist's `fetch(req)` handler is the worker entry point.

## Why Cloudflare Workers as the default

- Edge runtime, low cold-start latency (matters for voice)
- Scales to zero (no idle cost)
- Generous free tier (100K requests/day)
- Native support for Hono and the Web Fetch API used by VoiceForge core

## Phase 1 deliverables

- `wrangler.toml` template generated by the wizard
- Helper script `scripts/deploy.mjs` that wraps `wrangler deploy`
- Reference `templates/app/src/index.ts` that exports a default fetch handler

## Required environment

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN` (with Workers deploy permissions)

Plus all secrets needed by the chosen adapters (Twilio, ElevenLabs, Anthropic, Supabase) bound as Worker secrets via `wrangler secret put`.
